## Predict Before You Delete

For this exercise, I picked three existing lines in `js/todo.js`, predicted what would break before deleting each one, temporarily deleted it, tested the app in the browser, recorded what actually happened, and then restored the original line exactly where it was.

### Line 1: `addEventListener` line

**Line selected:** `deleteButton.addEventListener('click', () => {` inside the `addTask` function.

**Prediction:** I predicted that deleting only the opening line of this event listener would leave its callback body (`item.remove(); updateStatus();`) and closing `});` behind with no matching opening call. That would be a JavaScript syntax error, which stops the entire script from running — not just the delete button. So I predicted adding, completing, and deleting tasks would all stop working.

**Observed result:** Typing in the input still worked, but clicking "Add" did nothing. No task appeared in the list, and the page still showed "No tasks yet" and "0 tasks remaining." Because no task was created, the complete checkbox and Delete button could not be tested.

**Was the prediction correct?** Yes. The syntax error broke the whole script, so even adding a task (an unrelated feature) stopped working.

### Line 2: Page-changing line

**Line selected:** `span.textContent = text;` inside the `addTask` function.

**Prediction:** I predicted the task `<li>` would still be created and added to the list (checkbox and Delete button visible, task counter updates), but the task text itself would be blank since nothing sets the span's text.

**Observed result:** A new task row was created, the checkbox and Delete button appeared, and the task counter increased. However, the task text did not appear, so the row was blank.

**Was the prediction correct?** Yes, exactly as predicted.

### Line 3: Other line of my choice

**Line selected:** `input.value = '';` inside the form's submit handler.

**Prediction:** I predicted the task would still be added normally, but the input box would not clear after clicking "Add" — the typed text would remain in the box.

**Observed result:** The task was added normally, but the text I typed stayed in the input box instead of clearing.

**Was the prediction correct?** Yes. The task was still added normally, but the input box did not clear, exactly as I predicted.

All three lines were restored to their original position in `js/todo.js` after testing.
