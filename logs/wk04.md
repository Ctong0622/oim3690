### Session 07 - Running a Real Project and Responsive Design

On Tuesday, we learned more about how to use AI when working on a real website project. Before this class, I mostly thought about AI as a tool that could help me generate HTML and CSS, but this class showed me that there is a lot of planning that should happen before actually writing code. We learned about the process of going from a client interview to a proposal and PRD, and then using those documents to guide the actual website development. We also continued learning CSS layout and started focusing more on responsive design. I thought this class was especially useful because I can directly use this process for my Zhuoyue Mobility Mini Project.

1. I learned the overall process of building a real website for a client. The workflow we discussed was Client Interview → Proposal → PRD → Plan → Build → Test → Feedback → Improve. I think this is important because I should not immediately tell AI to "build me a website" before I understand what the client actually needs. For my Zhuoyue Mobility project, the client interview gives me the original information, and then I can organize that information before I start asking AI to write code.

2. I learned the difference between PROPOSAL.md and PRD.md. The proposal is mainly based on what I learned from the client, including who the audience is, what the purpose of the website is, what pages are needed, what content is available, and what style the client wants. The PRD, or Product Requirements Document, is more detailed and turns those ideas into requirements for actually building the website. I also learned that AI can help turn the proposal into a PRD, but I should still read, check, and correct the AI output instead of automatically accepting everything it creates.

3. Another important thing I learned was that I should build a website in smaller steps instead of asking AI to create the entire project at once. For example, I can first ask AI to build the navigation, then test it before moving on to the hero section. After that, I can work on the vehicle cards, booking section, and mobile layout one at a time. I think this approach makes the project easier to manage because if something goes wrong, I have a better idea of which change caused the problem. It also makes Git commits more useful because I can save my progress after completing smaller parts of the website.

4. We also continued learning CSS layout. We reviewed the box model and the difference between content, padding, border, and margin. Padding controls the space inside an element, while margin controls the space outside of it. We also continued working with Flexbox and Grid. I understand that Flexbox is especially useful for things like navigation bars, buttons, and groups of items that mainly need to be arranged in one direction. Grid is more useful when I want to organize content into rows and columns. For example, I think Grid will be useful for displaying different cars on my Zhuoyue Mobility website.

5. We started focusing more on responsive design and how the same website should work on different screen sizes. I learned that responsive design does not mean simply making the desktop website smaller. The layout should actually adapt depending on whether someone is using a desktop, tablet, or phone. We learned about the viewport and media queries, which can change CSS rules when the screen reaches a certain size. I also learned that I can use Chrome DevTools to resize the webpage and test different screen sizes. When testing, I should look for things like text becoming too small, images going outside the screen, cards not stacking correctly, or navigation becoming difficult to use.

## Summary for Session 7

Class 7 helped me understand that building a real website with AI involves much more than just generating code. I need to understand the client's needs first and use the Client Interview → Proposal → PRD → Plan → Build → Test → Feedback → Improve process. I also learned why it is better to build a website in smaller sections and test each section instead of asking AI to generate everything at once. The CSS part of the class also helped me connect Flexbox, Grid, the box model, and responsive design to an actual website project. I think this session was especially useful for Mini Project 1 because I can now see how the planning documents and the coding process connect together. For Zhuoyue Mobility, I can use the proposal and PRD to guide what I ask AI to build instead of letting AI decide what the website should contain.


### Session 08 - Reading AI-Generated Code and Responsive Design

On Thursday, we focused more on reading and understanding AI-generated code. This was useful because I have been using AI to help me build websites, but sometimes it is easy to focus only on whether the final webpage looks correct. This class made me think more about understanding what the code is actually doing before I accept it. We also reviewed CSS selectors, the box model, Flexbox, and Grid, and then went deeper into responsive layouts and media queries. I think this session helped connect using AI with actually learning how to read and change the code myself.

1. One of the most important things I learned was the process Read → Predict → Run → Compare → Change. When AI gives me code, I should first read it and try to understand what it does. Then I should predict what I think will happen before I run the website. After I test it in the browser, I can compare the actual result with my prediction. If something is different or does not work correctly, I can change the code and test it again. I think this is a better way to use AI because I am not just copying code without understanding it. It also helps me notice when AI gives me code that is too complicated, uses the wrong file path, adds something I did not ask for, or creates a bug.

2. We learned more about how to read CSS selectors. A selector tells CSS which HTML elements should receive a certain style. For example, an element selector can style every element of one type, a class selector uses a period, and an ID selector uses a `#`. We also looked at descendant selectors. For example, `nav a` means that the CSS rule applies to every `<a>` element inside a `<nav>`. I understand these basic selectors better now, but I still need practice reading more complicated CSS when several selectors and rules are used together.

3. We reviewed the CSS box model, Flexbox, and Grid in more detail. The box model helped me understand how every HTML element has content, padding, border, and margin. We also reviewed that Flexbox is mainly one-dimensional, meaning it is useful for arranging items in a row or column, while Grid is two-dimensional and can control both rows and columns. I also learned more about `gap`, which can create consistent spacing between items in a Flexbox or Grid layout. I think using `gap` is easier to understand than adding different margins to every individual item.

4. I learned more about responsive Grid and some CSS properties that I had seen before but did not fully understand. For example, we looked at `repeat(auto-fit, minmax(200px, 1fr))`. I learned that `repeat()` is used to repeat columns, `auto-fit` lets the browser fit as many columns as possible, and `minmax()` gives each column a minimum and maximum size. I also learned that `1fr` means one fraction of the available space. Together, these properties can make a group of cards automatically adjust depending on the screen size. A desktop might show three cards in one row, a smaller screen might show two, and a phone might show only one card per row.

5. We continued learning responsive design and media queries. A media query lets CSS use different rules depending on the size of the screen. For example, a navigation bar might be horizontal on a desktop but change into a vertical layout when the screen becomes smaller. We also talked about what makes a website mobile-friendly. The text should still be readable, images should stay inside their containers, navigation should remain usable, buttons should be easy to tap, and different sections should not overlap. I also learned that flexible sizes such as `width: 100%` and `max-width` can sometimes work better than using a large fixed width that may not fit on a phone.
