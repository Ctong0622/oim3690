### Session 09 - Mini Project 1 Presentation and Peer Feedback

On Tuesday, we presented our Mini Project 1 websites and received feedback from classmates. I presented my Zhuoyue Mobility website, which is a website for an EV and new-energy vehicle rental company in China. This was useful because I was able to see how other people interacted with the website without me explaining every feature to them. I also received a lot of feedback about what worked well and what could be improved in the next version.

1. One of the main positive comments I received was that the website is clean, professional, and easy to navigate. Several classmates liked the vehicle cards because they make it easy to compare information such as the vehicle, price, range, seats, and availability. I also received positive feedback about putting the Rent/Contact option in the navigation because renting a vehicle is the main action I want users to take.

2. People also liked that the website can switch between Chinese and English. Since Zhuoyue Mobility is based in China, I think having both languages makes the website more useful for its actual audience. Classmates also liked that the design and green color scheme fit the EV theme and that the website is tailored to the client's business instead of looking like a completely generic website.

3. The availability feature and rental application form also received positive feedback. Users can see whether a vehicle is available, booked, or under maintenance, and the rental form allows them to choose a vehicle and enter their information. One useful piece of feedback was that a vehicle marked as booked or under maintenance should not still allow the user to start a rental request. I think disabling the Rent button for those vehicles, or showing when they will become available again, would make the website more logical and prevent users from getting false expectations.

4. I received several suggestions for improving the amount of information on the website. Multiple classmates suggested adding more photos for each vehicle instead of only showing one main photo. Some also suggested adding more detailed vehicle information, a price filter, customer reviews, and a clearer explanation of the rental process. For example, the website could explain what documents customers need and the basic steps from submitting a rental request to picking up the vehicle.

5. Another important part of the feedback was improving the website as a complete user experience. Suggestions included adding a privacy-policy checkbox to the rental form, testing the rental form from beginning to end, removing the extra contact block at the bottom, and possibly replacing some emojis with more professional icons. These comments helped me realize that even when the website looks complete, I still need to test whether every feature makes sense from the user's perspective.

## Summary for Session 9

Session 9 was useful because I received feedback from people who were seeing and using my website from a user's perspective. The strongest parts of my project were the clean design, simple navigation, bilingual feature, vehicle cards, availability information, and rental application form. The main improvements I would consider are adding more vehicle photos and information, explaining the rental process more clearly, adding filters and customer reviews, improving the privacy information on the form, and preventing users from trying to rent vehicles that are unavailable. I learned that feedback is not only about whether a website looks good. It can also reveal problems with the user experience and features that I may not notice while building the website myself.


### Session 10 - HTML Forms and Introduction to JavaScript

On Thursday, we learned about HTML forms and how websites can collect information from users. We worked with form elements such as labels, inputs, buttons, and different input types. We also learned about GET and POST and tested how form data is sent. Later in class, we created a simple To-Do App using HTML, CSS, and JavaScript and started reading the JavaScript code to identify parts that we did not understand.

1. I learned how the `<form>` element works and how the `action` and `method` attributes control what happens when a form is submitted. The `action` tells the browser where the form data should be sent. In class, we used `https://oim.zhili.dev/echo/view` as the teaching endpoint so that we could see the information being sent by the form.

2. I learned the difference between GET and POST. With GET, the submitted form information is placed in the URL, so I could see information such as the username after submitting the form. With POST, the information is sent in the request body instead of being added directly to the URL. Testing both methods helped me understand the difference more clearly than only reading about them.

3. We also learned more about different form fields and their attributes. I practiced using `type="text"` for a name, `type="email"` for an email address, `type="password"` for a password, and a `<textarea>` for a longer message. I also learned that the `name` attribute is important because it identifies the data when the form is submitted. The `required` attribute provides basic validation by preventing the form from being submitted when a required field is empty.

4. I created a `contact.html` page with name, email, and message fields. I added matching labels and required validation for each field. I also used CSS to add spacing, visible focus states, and a hover effect on the submit button. This exercise helped me see how HTML and CSS work together in a real form instead of only using them for static content.

5. Later in class, we started working with JavaScript through a simple To-Do App. The app can add a task, mark a task as completed, and delete a task. Looking at `todo.js` was much more difficult for me than reading HTML or basic CSS because there were many methods, symbols, and commands that I had not used before. Instead of only accepting the generated code, I tried to identify specific parts that I did not understand so that I could learn what they do.
